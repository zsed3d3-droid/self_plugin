# Continuous product and UX loop

시장 문제 조사 → 사용자의 과업과 지원 범위 → 작동하는 컨테이너 제품 → 실제 화면·과업 진단 → 원인 확인 → 좁은 수정 → 같은 입력·경로 재검증 → 이유·반례·한계 기록을 반복합니다. 지원 범위를 완성한 제품을 보존하고 다음 문제로 이동합니다.

이것은 에이전트 실행 계약이며 별도 모델 호출 daemon이나 자동 스케줄러가 아닙니다. 실행 기간·예산·중단은 해당 사용자의 실제 허가와 런타임 한도를 따릅니다. 측정할 수 없는 잔여 토큰이나 만족도를 추정하지 않습니다.

각 수정/재빌드 전에 `../preservation/preserve-product.py`로 소스와 실행 이미지 태그를 보존합니다. DB·업로드·출력은 별도 백업 계약을 만듭니다. 백업을 만든 시점의 restore 상태와 나중에 실제 복원한 결과를 따로 기록합니다. 이전 결과, 오류, 테스트 실패, 사용자 자료를 삭제하지 않습니다.

WHY 기록은 과업, 관찰된 증상, 확인된 원인/가설, 변경, 같은 과업의 검증, 반례, 미검증·누락을 포함합니다. 작성자 주장과 독립 확인, 브라우저 기능 통과와 사용자 취향을 구분합니다. 새 사례는 assistant 근거로 저장하고 다음 제품의 선택/제외 이유를 남깁니다.

공개 요약은 `../../knowledge/`에서 확인합니다. 실제 제품·이전 버전·화면·DB와 실패 자료는 개발자의 로컬 보관소에 유지하며 이 패키지에 반입하지 않았습니다.
