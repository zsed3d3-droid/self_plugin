# Scenario adapter: selected Anti-slop / Unslop UI

이 어댑터는 원본 skill 전체를 실행하지 않는다. 과업에서 관찰한 문제에 맞는 규칙만 `rules.json`에서 골라 DESIGN·수정·같은 과업 재검증에 연결한다. 이 경로는 독립 실험이며 기존 제품이나 전역 스킬 설치를 변경하지 않는다.

적용 순서는 현재 과업 → 화면/DOM/키보드 관찰 → 가능한 원인 → 최소 변경 → 반례 → 같은 입력·동선의 재검증이다. 사용자가 좋아한 부분과 의미 있는 그룹 경계는 보존한다. 단순히 카드가 있다는 이유로 삭제하지 않는다.

선택한 강점은 중첩 경계의 목적, 장식 아이콘의 정보 기여, 색에 의존하지 않는 상태, 네이티브 조작과 포커스다. 고정 비율·글꼴 금지·모든 작업의 보고서·반복 모드 질문·강제 모션은 제외한다.

현재 fixture의 같은 과업: **검토 대기 중인 검색 필터 작업의 담당자를 찾고 상세를 키보드로 연 뒤 돌아온다.** BEFORE/AFTER는 작업3건의 제목·담당·상태·기한을 공유한다. COUNTERCASE는 같은3건을 서로 다른 작업공간으로 묶어, 의미 있는 선택 경계와 사람 표식은 유지한다.

색·위치·문구를 바꾼 전후 캡처, 검색/키보드·포커스·그룹 검증은 tests/browser-check.mjs에서 실행한다. 통과는 정해진 synthetic fixture의 관찰 결과다. 실제 사람의 완료 시간·선호·제품 채택으로 확대하지 않는다.

## 이 실험에서 실제로 추가한 판단

첫 기능 검사에 통과해도 연속 동선은 별도로 확인한다. 작업공간을 고른 뒤 검색하면 선택이 초기화되는 결함을 실제로 재현했다. 이 경우 선택 상태는 필터와 독립적으로 소유하고, 화면 재구성이 그 값을 재사용하게 한다.

포커스의 CSS radius 선언만으로 시각 일치를 확정하지 않는다. 실제 radio의 네이티브 outline은 사각형으로 남았다. 의미·키보드 동작을 유지하면서 해당 outline만 원형 표시로 대체하고 실제 캡처에서 확인한다. 두 판단은 로컬 실험 근거이며 저자의 검증 결과나 사용자 채택으로 승격하지 않는다.
