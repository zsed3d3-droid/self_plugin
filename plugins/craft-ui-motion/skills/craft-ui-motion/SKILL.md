# Craft UI & Motion

기존 제품과 사용자 과업을 먼저 확인한다. 색상·폰트·정보 밀도·다크 모드·테두리·모션을 일괄 강제하지 않는다. 브랜드가 있으면 유지하고, 개인용 새 제품은 그 제품에 맞게 정한다.

카드 중첩과 반복 KPI가 주 작업을 방해하면 제목·정렬·여백·표/목록으로 단순화한다. 여백을 없애서 해결하지 않는다. 카드·모달·그림자·아이콘은 실제 기능에 따라 사용한다. 모든 화면을 보더로 나누거나 단색으로 제한하지 않는다.

사용자 입력/결과·공간 변화에 도움이 될 때만 모션을 적용한다. CSS/기존 의존성을 먼저 쓰고 transform/opacity를 우선한다. reduced motion과 중단/반복 입력을 지원한다. 성능은 실제 측정하며 60fps를 보장한다고 쓰지 않는다. 전체 화면의 도입 애니메이션이나 수치 롤링을 기본으로 붙이지 않는다.

키보드 경로·보이는 포커스·명확한 라벨·대비를 유지한다. 입력기의 이중 포커스 표시를 정리하더라도 실제 포커스를 없애지 않는다. 팝오버는 트리거와 연동하고 클리핑·ESC·포커스 복귀를 확인한다. 표·본문·뷰어의 스크롤은 사용자 행동에 맞게 설계한다.

레이아웃 결함은 responsive-layout-guard를 필요한 컴포넌트에 적용한다. 새 UI/모션 그래픽은 scenario-ui-ux의 검색 도구와 모션 가이드를 사용한다. 오래된 화면별 처방을 다른 제품의 전역 불변식으로 전파하지 않는다.
