# 사용자 판단 기반 개발

현재 저장소와 서비스의 하네스를 읽고 적용한다. 개발 흐름은 **gstack**을 기본으로 유지한다. 개인 판단은 프로젝트의 비공개 정책 경로에서 읽는다. 이 배포에는 사용자 원문이나 판단 JSON이 없다. [decision-application.md](references/decision-application.md)의 연결 방법을 따르고, 미연결 상태를 검증 통과로 표시하지 않는다.

## 상황을 판단하고 자동 진행

상황별 경로는 [routing.md](references/routing.md)를 따른다. 에이전트가 현재 과업·목적·변경 범위를 판단해 맞는 스킬을 자동으로 읽고 실행한다. 사용자에게 호출할 스킬을 고르게 하지 않는다. `.devtools/route-development.py`는 분류한 상황의 실행 계획을 출력한다. 분류 근거가 부족할 때만 중요한 질문을 한다. 라우터 출력은 스킬 실행이나 개인 경험 의미검색 성공의 증거가 아니다.

- **신규/모호한 요구:** 필요한 깊이로 대화한 뒤 사용자·행동·성공 결과·중요 예외·미확정 가정을 짧고 명확하게 정리한다. 요구→구현→검증을 연결한다. 이미 정한 내용을 반복 승인받지 않는다.
- **신규 UI/흐름:** `text-wireframe-planner`와 `scenario-ui-ux`로 진입→행동→결과를 만든다. `ux-judgment`에서 관련 디자이너의 판단과 반례만 골라 레퍼런스·DESIGN.md·수정·동일 과업 검증에 연결한다. 공유 컴포넌트·토큰을 쓰고 화면/영역별 밀도를 고른다. 사용자의 감각적 표현은 실제 화면과 연결해 기억한다.
- **구현/버그:** Superpowers에서는 **TDD만** 가져온다. 동작 변경은 필요한 최소 실패 재현→수정→관련 확인으로 진행한다. 버그 재현은 원인 확인에 사용한다. 사소한 문구·스타일·명확한 컨트롤 수정에 새 테스트·큰 모델 판단·추가 승인을 강제하지 않는다.
- **리뷰/QA:** gstack-review의 코드 리뷰와 실제 사용자 시나리오 QA를 구분한다. `live-browser-session`으로 사용자가 되어 핵심 과업·불편·버그를 확인하고 개발 범위 안의 결함을 수정한다. 넓은 QA가 필요하면 gstack-qa를 연결하며 같은 검증을 중복하지 않는다. 리뷰만 요청했으면 파일을 바꾸지 않는다.
- **전달:** `plain-writing`으로 변경 결과·근거·실행한 검사·미검증을 간결하게 전달한다. 기능 테스트와 사용자 만족을 따로 기록한다. 화면·문체·밀도 선택은 사용자의 기호를 우선하고 정확성·보안·접근성 계약을 함께 지킨다.

테스트가 중복·진부해지면 독립적인 회귀 신호를 유지하며 묶는다. 사용하는 계약/기능이 사라진 테스트만 제거하고, 실패를 숨기기 위해 삭제하지 않는다. 단순히 테스트 수를 줄이는 목표를 만들지 않는다.

## 행동별 권한과 도구 사용

처음부터 필요한 도구를 폭넓게 사용할 수 있게 구성하되 **각 행동·이벤트별 실제 허용 범위**를 적용한다. 원본 조회는 원본 read-only, 산출물 생성은 지정 출력 경로만 write로 분리하고 실행 샌드박스/컨테이너 마운트에서 강제한다. 이 문서 자체가 실행 권한을 부여하거나 경계를 강제하는 기능은 아니다.

프로젝트/주제에 유효한 사전 허가가 없는 유료 도구는 사용 직전에 목적·비용 범위를 확인받는다. 로그인·저장된 카드·YOLO 모드는 과금 허가가 아니다. 가능한 무료 대체를 먼저 확인하고 유료 자산은 기본으로 사용하지 않는다. 현재 요청에 포함된 가역적 로컬 작업에 재승인을 요구하지 않는다. 실제 권한을 넘는 배포·외부 발송·운영 변경은 별도다. 자세한 계약은 [execution-and-data.md](references/execution-and-data.md).

## 경험을 다음 판단에 연결

요청·원천 이벤트·판단·행동·산출물·사용자 평가를 프로젝트/주제/목적별로 연결한다. 주제가 다른 회의·요청의 세션은 섞지 않는다. 지금 목적에 맞는 근거를 회수하고 출처·버전·적용 범위를 함께 읽는다.

반복된 교정은 같은 적용 범위의 규칙으로 승격하고 근거와 변경 버전을 남긴다. 중복 import를 반복 지적으로 세지 않는다. 잘못 회수된 근거는 상황별 제외/정정으로 다음 검색에 반영한다. 단순 문장 유사도나 AI 자체 점수로 사용자의 채택을 대신하지 않는다.

재시도는 작업에 기록한 상한을 따른다. 한도를 소진하면 `retry_budget_exhausted` 이벤트와 시도 근거를 남기고 해당 작업의 추가 시도를 멈춰 사용자 판단을 받은 뒤 다음 단계로 간다. 세션/요청 ID 변경으로 한도를 우회하지 않는다. [feedback-loop.md](references/feedback-loop.md)는 검색·오답노트·규칙 승격의 데이터/인수 계약이며 현재 전체 기억 시스템이 구현됐다는 뜻은 아니다.

## 컨테이너·데이터 하네스

모든 신규 서비스는 Dockerfile·Compose·healthcheck·영속 데이터 볼륨을 제공하고 실제 빌드·기동·재시작 보존을 검증한다. 승인된 **MLX Metal 음성 엔진만** Mac 호스트 실행 예외로 `.devtools/services.json`에 사유와 health URL을 기록한다.

제품별 결과물은 삭제하지 않는다. 연속 제품 루프에서는 첫 구현과 각 수정·재빌드 전에 소스 스냅샷·실행 이미지의 별도 태그·파일 해시를 남긴다. DB·업로드·기존 출력·실패 캡처·변경 이유도 버전별로 보관한다. 인증·비밀 파일은 일반 소스 보관물과 분리한다. 보관 실패 시 재빌드를 멈추며 기존 기록을 덮어쓰거나 prune/down -v로 지우지 않는다. 소급해 첫 상태를 복원하지 못한 경우 그 누락을 기록한다. 현재 UX Lab에는 `harness/preservation/preserve-product.py`를 재빌드 전 명시적으로 실행한다.

신규 독립 실서비스의 DB는 설정 시점에 공식 자료로 확인한 **최신 안정 PostgreSQL + 영속 볼륨**을 기본으로 한다. SQLite는 명시적인 데모/시험에만 사용한다. 기존 플랫폼의 공유 DB/마이그레이션 계약은 그대로 적용한다. 현재 검토용 SQLite 데모의 원본 판단을 임의로 삭제·이관하지 않는다.

`python3 .devtools/check-containers.py`는 선언·파일·health·볼륨의 정적 누락 검사다. 실제 Docker 실행과 데이터 보존 검사는 별도로 수행하고 미실행을 통과로 표시하지 않는다.
