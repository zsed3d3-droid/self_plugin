# 상황별 자동 개발 경로

에이전트가 현재 요청의 목적·대상 서비스·변경 범위·신규 흐름 여부를 먼저 분류한다. 사용자는 요구사항과 판단을 제공하고, 도구/스킬 선택은 에이전트가 담당한다. 한 요청에 여러 상황이 있으면 필요한 단계만 합쳐 중복을 제거한다.

| 상황과 근거 | 자동 적용 경로 | 최소 결과 |
| --- | --- | --- |
| 신규 제품/모호한 목표 | gstack-office-hours 또는 spec → 필요한 경우 gstack-plan-eng-review | 짧은 요구 요약, 핵심 행동, 성공/실패 조건 |
| 새 화면·화면 동선 변경 | text-wireframe-planner → scenario-ui-ux의 레퍼런스·디자이너 판단·DESIGN.md → 구현 → 브라우저/디자인 gate | 진입/행동/결과·구조 원인과 수정·실제 검증 |
| 명확한 UI 버그·입력 불가 | 원인 재현 → 관련 컴포넌트 수정 → 해당 브라우저 과업 재실행 | 같은 입력으로 결함이 사라짐. 추가 인터뷰/전면 설계 없음 |
| API·DB·상태 변경 | 현재 계약 확인 → 필요한 설계 검토 → TDD → 관련 API/데이터 확인 | 입력·오류 일관성, 필요한 동작·데이터 보존 |
| 문구·설명 작성/수정 | plain-writing → 해당 문맥 검토 | 짧고 구체적인 결과 문구 |
| 모션·드로어·전환 수정 | scenario-ui-ux 모션 지침 → 전환 중간·키보드·reduced motion 확인 | 움직임 중 정보가 튀거나 어긋나지 않음 |
| 카드 중첩·구조 결함 | scenario-ui-ux → unbox-ui + 필요한 responsive-layout-guard | 영역 관계·여백·주요 과업이 유지됨 |
| 디자인 규칙 자동 검수 | scenario-ui-ux의 design-hooks → 프로젝트 수정 직후 검사·완료 gate | 토큰 검사와 실행 UX/독립 리뷰 분리; 현재 hash·누락 단계·수정 예산 검사 |
| 코드 리뷰 요청 | gstack-review의 관련 범위 | 근거 있는 발견. 리뷰만 요청하면 무수정 |
| 사용자가 불편/버그 지적 | 원천 이벤트와 현재 과업 회수 → 재현/분석 → 수정 → 결과 피드백 연결 | 지적·원인·조치·결과의 오답노트 |
| 반복 교정 | 기존 규칙/반례 검색 → 동일 범위 규칙 승격·버전 기록 | 다음 유사 과업에서 적용하고 결과 평가 |

분류의 근거가 검색 결과와 다르면 사용자 현재 요청을 우선하고 잘못 회수한 근거를 정정한다. 상황별 레이블 라우터는 의미검색을 대신하지 않는다. 과거 원문에서 스킬 이름이 등장했다는 이유만으로 현재 상황에 적용하지 않는다.

gstack을 기본 개발 경로로 유지한다. Superpowers의 전체 워크플로우·반복 승인·에이전트 팀을 추가하지 않고, 필요한 TDD 동작만 사용한다. 도구 설치/인증이 없으면 대체 검증을 실제로 수행하고 도구 실행을 주장하지 않는다.
