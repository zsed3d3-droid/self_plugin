# Live Browser Session

에이전트는 사용자의 평소 Chrome을 쓰지 않는다. 새 임시 프로필로 Chrome을 따로 열고, 사용자가 그 창에서 직접 로그인한 뒤 Playwright로 연결해 작업한다. 작업이 끝나면 Chrome을 닫고 프로필을 지운다. 로그인 세션이 남지 않게 하는 것이 이 절차의 끝이다.

스크립트 경로는 이 스킬 폴더의 `scripts/`이다. Claude Code와 Codex 모두 셸로 실행한다.

## 1. 시작

```sh
bash scripts/browser-session.sh start https://대상-주소/
```

- 출력되는 `port`, `profile`, `pid`를 기록한다. `profile`은 종료할 때 필요하다.
- 사용자에게 열린 창에서 직접 로그인해 달라고 요청하고, 완료 답을 받은 뒤 진행한다. 에이전트는 아이디·비밀번호·OTP를 입력하거나 받지 않는다.
- 이미 포트가 쓰이고 있으면 기존 세션인지 확인한다. 다른 세션이면 `LBS_PORT`를 바꿔 시작한다.
- Codex는 샌드박스 설정에 따라 앱 실행과 `127.0.0.1` 접속에 승인이 필요할 수 있다. 승인 요청 이유를 "로그인용 전용 Chrome 실행"으로 밝힌다.

## 2. 연결

Playwright는 설치된 `playwright-core`를 쓴다. 없으면 작업 폴더 밖 임시 폴더에 설치하고 `PLAYWRIGHT_CORE`로 경로를 넘긴다. 전역 설치하지 않는다.

```js
import { guardWrites, maskPersonalData, collectErrors } from './scripts/page-guard.mjs';
const { chromium } = await import(process.env.PLAYWRIGHT_CORE || 'playwright-core');
const browser = await chromium.connectOverCDP('http://127.0.0.1:9333');
const page = await browser.contexts()[0].newPage();   // 사용자가 로그인한 컨텍스트
const blocked = await guardWrites(page);                // 기본: 읽기 요청만 통과
const errors = collectErrors(page);
// ... 작업 ...
await page.close();
await browser.close();                                  // 연결만 끊는다. Chrome은 4단계에서 닫는다
```

- 쿠키·토큰·저장소(localStorage 등) 값을 읽거나 출력하지 않는다. 세션은 브라우저 안에서만 쓴다.
- 사용자가 열어 둔 탭은 건드리지 않고 새 탭에서 작업한다.

## 3. 작업

### 3.1 공통 안전 규칙

- **쓰기 차단이 기본이다.** `guardWrites`는 GET·HEAD·OPTIONS만 통과시키고 나머지를 막는다. 막힌 요청 목록을 결과에 그대로 보고한다.
- **허용은 좁게 연다.** 꼭 필요한 쓰기만 `allow`에 `"METHOD /경로"` 정규식으로 넣는다. 예: 데모 역할 전환 `/^POST \/api\/workrelay\/auth\/demo-switch\//`. 운영 환경의 저장·삭제·발송·결재는 사용자에게 대상과 영향을 알리고 승인받은 것만 연다.
- **읽기에도 부수효과가 있는지 코드로 확인한다.** 화면을 여는 것만으로 상태가 바뀌거나(예: 관리자가 열면 '검토 중'으로 자동 변경) 조회 기록·점검 결과가 저장되는 경우가 있다. 그런 화면은 영향이 없는 대상(종료된 건 등)만 열거나 해당 요청을 막는다.
- 상태를 바꾸는 버튼(저장, 완료, 삭제, 실행, 발송)은 누르지 않는다. 기능 테스트에서 눌러야 하면 3.3절을 따른다.

### 3.2 화면 캡처(매뉴얼·보고용)

- 화면 크기는 1440×900을 기본으로 하고, 긴 화면은 `fullPage`와 `clip`으로 필요한 높이만 찍는다. 옆에서 열리는 상세 창(drawer)은 전체 페이지가 아니라 보이는 영역으로 찍는다.
- 개인정보를 가린다: 다른 사람의 이름·이메일·사번, 업무상 민감한 값(예: 개발 중 소재명, 매출 금액).
  - `maskPersonalData(page, { names, keep })`는 이메일·9자리 사번과 **글자가 정확히 같은** 이름만 흐리게 한다. 이름 목록은 화면 응답(JSON)의 사람 이름 칸에서 모으고, 메뉴·버튼 단어가 섞이지 않았는지 확인한다. 본인처럼 보여도 되는 이름은 `keep`에 둔다.
  - 이미 받은 이미지(사용자가 붙여 준 화면 등)는 좌표를 정해 흐리게 처리한다.
- 찍은 뒤 **이미지를 직접 열어** 가림이 빠지거나 넘친 곳이 없는지 확인한다. 작은 글자는 확대해서 본다. 메뉴·제목이 가려졌으면 범위를 줄여 다시 찍는다.
- 시스템이 만든 가상 인물(데모 계정)인지 코드로 확인되면 가리지 않아도 된다. 확인하지 못하면 가린다.
- 예시로 쓸 대상을 사용자와 맞춘다. 보여 주지 않기로 한 다른 예시 데이터는 흐리게 처리하고 그림 설명에 그 사실을 적는다.

### 3.3 실제 웹페이지 기능 테스트

- 테스트 대상·환경(개발/운영)·허용할 쓰기 요청을 먼저 정하고 사용자 확인을 받는다. 운영에서는 데모·시험 데이터나 영향이 없는 대상만 쓴다.
- 확인 항목을 코드로 적는다: 화면 이동, 버튼 노출, 결과 문구, 응답 상태, 역할별 메뉴 차이 등. 눈으로 본 것만으로 통과라고 하지 않는다.
- `collectErrors(page)`로 페이지 오류·콘솔 오류·실패한 요청을 모은다. 오류 알림(toast) 문구도 확인한다.
- 실패하면 그 시점 화면을 찍고, 오류 문구·요청·재현 순서를 함께 보고한다. 원인을 코드에서 찾았으면 파일과 줄을 적고, 찾지 못했으면 확인 필요로 남긴다.
- 결과 보고에는 통과·실패 항목, 막힌 요청 목록, 허용해서 실제로 보낸 쓰기 요청, 수집한 오류를 모두 적는다.

## 4. 종료와 정리(필수)

```sh
bash scripts/browser-session.sh stop --profile <start가 출력한 profile>
```

- Chrome을 CDP `Browser.close`로 닫고(안 되면 프로세스 종료), 포트가 닫힌 것을 확인한 뒤 프로필 폴더를 지운다.
- `start`가 만든 표시 파일(`.live-browser-session`)이 없는 폴더는 지우지 않는다. 다른 폴더를 지정했다는 뜻이므로 경로를 다시 확인한다.
- Chrome이 아직 실행 중이면 프로필을 지우지 않고 멈춘다. 사용자에게 창을 닫아 달라고 하고 다시 실행한다.
- 작업 중 만든 임시 파일 중 공유하지 않을 것(이름 목록, 원본 캡처 등)도 지운다. 결과물로 넘긴 이미지만 남긴다.
- 정리 결과를 사용자에게 알린다: 닫힘 여부, 지운 프로필 경로, 남긴 파일.

작업이 길어져도 세션을 열어 둔 채 끝내지 않는다. 이어서 써야 하면 사용자에게 열어 둔다고 알리고, 마지막 작업에서 반드시 4단계를 실행한다.

## 하지 않는 것

- 사용자의 기본 Chrome 프로필이나 이미 로그인된 다른 브라우저에 연결하지 않는다.
- 원격 디버깅 포트를 `127.0.0.1` 밖으로 열지 않는다(`--remote-debugging-address` 등을 쓰지 않는다).
- 로그인 정보·세션 쿠키를 파일로 저장하거나 다음 작업에 재사용하지 않는다.
- 허용하지 않은 쓰기 요청을 우회해서 보내지 않는다(예: 페이지 밖에서 `fetch`로 직접 POST).
