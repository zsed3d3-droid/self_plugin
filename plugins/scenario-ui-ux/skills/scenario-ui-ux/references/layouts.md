# 시나리오별 레이아웃 결정

| 사용자 과업 | 출발점 | 피할 것 | 확인할 결과 |
| --- | --- | --- | --- |
| 수백 건 비교·선별 | 검색/필터 + 정렬 가능한 표 + 선택 상세 | 항목마다 카드 안 속성 카드 | 비교 필드 유지, 선택/필터 복귀 |
| 긴 문서 읽고 근거 확인 | 읽기 폭을 제한한 본문 + 인접 근거 | 문단마다 테두리, 장식 KPI | 인용 위치, 확대/좁은 화면 |
| 여러 대상 탐색 | 목록 또는 이미지/메타데이터 카드 | 의미 없는 동일 카드 반복 | 탐색 단서와 다음 행동 |
| 승인·결정 | 대상·변경점·근거 + 명확한 결정 영역 | 모든 정보를 모달에 압축 | 권한, 실패 입력 보존, 중복 방지 |
| 순서 의존 등록 | 단계별 입력 + 진행/뒤로 | 단순 검색에 불필요한 위저드 | 이전 값 보존, 오류 위치 |
| 실시간 작업 공간 | 핵심 작업 + 필요한 보조 패널 | 모든 공간을 칸으로 채움 | 포커스·선택·화면 폭 보존 |
| 원리 설명/온보딩 | 큰 핵심 도형 + 단계 전환 | 문장마다 카드, 매 요소 입장 효과 | 설명 없이도 관계를 이해함 |

이 표는 시작점이다. 실제 콘텐츠 길이·빈도·기기와 기존 디자인을 우선한다.
데스크톱 split view는 좁은 화면에서 명시적 상세 화면/패널로 전환하고 목록 위치를 보존한다.
여백은 같은 그룹 안보다 그룹 사이에 더 크게 배정한다. 한 화면에 한 종류의 간격만 반복하지 않는다.

## 밀도 조정

같은 화면에서도 목록·본문·검색 도구·상세 패널의 밀도를 따로 판단한다. 공통 컴포넌트의 역할은 일관되게 유지하면서 영역별 행 높이, 간격, 표시할 보조정보, 읽기 폭을 조절한다.

사용자가 “좀 더 여유 있게”, “한 번에 더 많이”, “깔끔하게”라고 하면 기존 화면과 과업을 보고 어느 영역의 무엇을 바꾸는지 짧게 설명하고 작업한다. 이 표현들을 고정된 수치나 공통 디자인 용어로 단정하지 않는다. 확인된 전후 화면과 피드백을 연결해 해당 맥락에서의 약속으로 남긴다. 자세한 기록 방식은 [개인 UI 판단](personal-ui.md)을 따른다.
