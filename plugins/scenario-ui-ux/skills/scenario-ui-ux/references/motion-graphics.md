# 인터랙션과 모션 그래픽

## UI 인터랙션

Motion: https://github.com/motiondivision/motion (MIT)
Anime.js: https://github.com/juliangarnier/anime (MIT)

기존 의존성을 확인한 뒤 선택한다. Motion의 layout/shared element 전환은 선택 대상의 연속성에, Anime.js 타임라인은 SVG 경로·단계적 설명에 적합하다. 단순 hover는 CSS로 충분하다. 패키지 API는 설치 버전의 공식 문서로 확인한다.
움직이는 텍스트 아래에도 고정된 읽기 가능한 값과 accessible name을 유지한다. hidden/outgoing 레이어가 탭 순서에 남지 않게 한다.

드로어의 기존 Vaul 사용은 유지한다. 사용자는 Vaul을 유지보수 상태만으로 제외하자는 규칙을 거절했고, 교체를 직접 요청하기 전까지 사용하도록 선택했다. 신규 드로어에서도 후보로 사용할 수 있으며, 이 선택이 모든 화면에 Vaul을 설치하라는 지시는 아니다. 실제 결함이나 호환성 문제는 재현 근거와 함께 다룬다.

팝오버나 패널은 트리거의 위치·방향과 이동 경로를 맞춘다. `transform-origin`, 레이아웃 측정 시점, 이전/다음 레이어의 가시성을 함께 점검한다. 시작·중간·끝 프레임과 빠른 반대 동작에서 정보가 다른 위치에 잠깐 그려지거나 순간 이동하지 않아야 한다. 문제를 재현할 때만 느린 재생이나 프레임 캡처를 추가하고, 수정 뒤 같은 전환을 다시 확인한다.

## 설명 영상/그래픽

새 기능의 동작 원리를 설명할 때는 사용자 질문→핵심 관계→변화→결과를 storyboard로 정리한다. 실제 업무 수치와 도식 수치를 구분한다. 장면마다 설명하려는 관계와 핵심 도형 하나를 정하고, 큰 글자·여백·대비로 읽기 순서를 만든다. 검은 배경·보라색·별 배경을 고정 스타일로 사용하지 않는다.

1. 출처가 필요한 사실/수치를 확인한다.
2. 메시지와 장면별 시작/끝 상태·전환을 쓴다. 음성이 있으면 대본과 타임라인을 맞춘다.
3. HTML/SVG/Canvas/현재 프레임워크로 대표 장면을 실행한다. frame 값에 따라 결정되는 애니메이션은 재현 가능한 캡처/출력에 유리하다.
4. 시작·중간·끝과 장면 경계의 이미지를 확인한다. 텍스트 잘림, 도형 겹침, 대비, 빈 프레임과 이전 장면 잔상을 검사한다.
5. 영상 납품이 요청됐을 때만 렌더러/오디오 의존성을 추가한다. 웹 UI 모션 작업을 영상 제작 프로젝트로 확장하지 않는다.

MIT 기반 영상 후보: https://github.com/motion-canvas/motion-canvas
Remotion은 별도 회사 사용 조건을 확인해야 하며 기본 의존성이 아니다.

검토한 anything2explainer: https://github.com/Vincentwei1021/anything2explainer
2026-10-28 원본은 PolyForm Noncommercial 1.0.0이며 상업 사용은 저자 허가가 필요하다. 이 패키지는 그 코드·템플릿·프롬프트·자산을 포함하지 않는다. 필요 시 사용자 확보 라이선스와 사용 목적을 먼저 확인한다. 이 문서의 절차와 포함 예제는 독립 작성했다.

검증에는 현재 제품에서 실행한 전환과 실제 캡처를 사용한다. 예제 파일이나 렌더 결과가 없다면 실행 가능한 예제가 포함됐다고 보고하지 않는다.
