# 개인 UI 판단을 적용하는 방법

화면의 밀도·여백·깔끔함, 공유 컴포넌트, 모션 또는 이전 디자인 피드백을 다룰 때 읽는다. 기능적 요구를 충족하는 대안 중에서 사용자의 선호를 우선한다. 외부 개발자의 취향이나 자동 점수로 사용자 평가를 대체하지 않는다.

## 감각적인 표현을 구체적인 변화로 연결

사용자에게 디자인 전문 용어를 요구하지 않는다. “답답해”, “깔끔하게”, “더 많이 보이게” 같은 표현은 현재 화면·과업·영역을 보고 해석한다. 한 표현에 하나의 고정 수치를 대응시키지 않는다.

예를 들어 “답답하다”가 행 간격, 긴 문장, 중첩된 경계 중 무엇을 뜻하는지는 화면마다 다를 수 있다. 관찰 가능한 문제를 짚고 “목록 행 사이를 넓히고 반복 테두리를 덜겠습니다”처럼 바꿀 부분을 간단히 설명한다. 결과를 크게 달라지게 하는 불확실성이 있을 때만 짧게 확인하고, 명확한 작은 수정은 이어서 처리한다.

같은 표현과 결과가 반복해서 확인되면 해당 맥락에서의 약속으로 남긴다. 약속은 프로젝트→화면/컴포넌트→영역·기기·과업 범위로 적용한다. 여러 맥락에서 확인되기 전에는 전역 선호로 확대하지 않는다.

## 근거와 평가의 최소 기록

프로젝트의 기존 피드백/근거 저장소를 사용한다. 없으면 작업 기록에 필요한 항목만 남기며 별도 수집 시스템이 구현됐다고 주장하지 않는다.

| 항목 | 남길 내용 |
| --- | --- |
| 원문 | 사용자가 실제로 쓴 표현과 대화/이벤트 ID |
| 맥락 | 프로젝트, 화면·영역, 과업, 기기/화면 폭 |
| 해석 | 관찰된 문제와 AI의 해석. 미확정 해석은 가설로 표시 |
| 변경 | 조절한 행 높이·간격·보조정보·읽기 폭·경계 등과 전후 캡처/커밋 |
| 결과 | 기능 검사 결과와 사용자 평가를 별도 기록. 미평가는 미평가로 유지 |
| 적용 | 확인된 선호의 범위, 대체/거절된 해석, 이후 수정 근거 |

사용자가 해석을 정정하면 원문을 지우지 않고 정정과 대체 관계를 남긴다. 검색할 때는 현재 적용되는 해석을 우선하고 폐기된 해석을 확정 선호로 재사용하지 않는다. 반복된 수정 지시는 근거가 연결된 범위별 규칙으로 축적한다.

## 공통 구성과 자산

- 동일한 역할의 컴포넌트는 공유 구현과 의미 있는 색·간격·타입 토큰으로 통일한다. 반복 수정의 원인이 공통 구현에 있으면 관련 사용처에서 함께 해결한다.
- 목록·본문·온보딩 등 다른 과업은 서로 다른 밀도를 가질 수 있다. 공용 컴포넌트 사용이 모든 화면을 같은 구조나 밀도로 만드는 뜻은 아니다.
- 유료 UI 키트·폰트·이미지·컴포넌트 자산을 추가하지 않는다. 기존 자원과 무료 사용이 허용된 자산의 출처·라이선스를 확인한다.
- 컴포넌트 후보는 프로젝트의 실제 유지보수·접근성·상호작용 요구에 맞게 선택한다. 사용 중인 라이브러리를 근거 없이 교체하거나 신규 프로젝트에 무조건 설치하지 않는다.


## 공개 배포의 개인 자료 경계

개별 사용자의 채택/거절 원문, 이벤트 ID와 대화·이미지는 포함하지 않는다. 로컬 판단 기록이 연결되지 않았다면 개인 선호 검증을 실행했다고 주장하지 않는다. 프로젝트에서 확인한 피드백만 해당 과업과 화면 범위에 적용한다.
