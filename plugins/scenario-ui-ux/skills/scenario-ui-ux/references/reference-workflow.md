# 레퍼런스에서 내 제품의 결정으로

대상은 예쁜 화면 모음이 아니라 현재 기능을 쉽게 수행하게 하는 구조와 상호작용이다. 자료를 많이 보유하는 것과 한 화면에 여러 스타일을 섞는 것은 별개다.

1. 과업, 실제 콘텐츠, 사용 빈도, 기기, 성공/취소/오류를 정한다. 기존 화면과 사용자가 좋아한 부분을 먼저 본다.
2. reference-plan.py와 Pro Max 검색으로 후보를 찾고 공식 데모·설계 문서·오픈소스 구현을 연다. 사용자가 준 레퍼런스를 우선한다. 카탈로그는 출발점이며 과업에 맞는 다른 공개 사례도 탐색한다.
3. 구조/정보 위계의 기본 레퍼런스와 컨트롤/모션의 보완 근거를 구분한다. 필요한 부분만 가져오고 전체 디자인 시스템·라이브러리를 설치하지 않는다.
4. 각 근거에서 가져올 점 / 제외할 점 / 적용 위치 / 확인한 상태·기기 / URL·캡처를 남긴다. 공개 화면 참고가 소스·브랜드·이미지의 재사용 권리를 뜻하지 않는다.
5. 실제 한영 콘텐츠와 빈 상태를 넣어 한 방향으로 구현한다. DESIGN.md의 토큰과 컴포넌트로 출처들을 하나의 문법에 맞춘다.
6. 구현 화면과 선택한 기준을 비교해 주행동·노출 정보·클릭 경로·읽기 순서·상태 변화가 좋아졌는지 확인한다. 매번 사용자에게 모든 레퍼런스나 여러 스타일 승인을 요구하지 않는다.

## 예제 작업 앱의 적용 예

| 요구 | 가져올 점 | 제외할 점 | 확인할 결과 |
| --- | --- | --- | --- |
| 필요한 것만 보임 | Primer 점진적 공개: 기본 목록, 작성·보조 메모는 요청 시 | 매번 여러 단계를 거치는 위저드 | 목록→추가 창→저장→목록 |
| 드롭다운 완성도 | Radix Select의 트리거·선택표시·포커스·popup 경계 | 현재 vanilla 앱의 React 전환 | 클릭/키보드·메뉴 Escape·창 Escape |
| 기한 입력 | React Aria DatePicker의 날짜 필드/달력 상태 | 불필요한 시간·타임존 기능 | 없음·선택·작은 화면·초기화 |
| 좋아한 피드백 창 | 사용자 기존 창의 배치/간격/입력 강조 | 창 전체 재구성 | 기존 배치 유지, 선택창/radius 개선 |

이는 설계 판단이다. 공식 문서는 reference-catalog.json에 연결하고 실제 구현 결과는 앱 검증 기록을 따른다.

## 카탈로그와 검색의 한계

reference-catalog.json은 공식 문서의 주소와 자체 작성한 적용 메모다. 2026-10-29에 해당 문서를 열어 내용 존재를 확인했으며 모든 시각 상태를 검증한 것은 아니다. URL 조회만으로 visual_inspected를 true로 바꾸지 않는다. 스킬 공급원과 실제 화면 레퍼런스는 다른 종류의 근거다.

태그 검색은 제한된 한영 표현을 대응시킨다. 무관한 결과는 제외하고 질의를 구체화한다. 개인 기억의 의미검색·필터·재정렬·오회수 정정을 대신하지 않는다.
