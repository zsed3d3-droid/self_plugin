# Text Wireframe Planner

기존 요구사항과 화면을 확인하고 사용자·목표·시작 상태·행동·성공 결과를 정리한다. 이미 제공된 정보는 다시 묻지 않는다. 결과를 바꾸는 중요한 질문만 하고, 합리적으로 진행할 수 있으면 가정을 밝혀 계속한다.

한 시나리오의 진입→핵심 행동→결과와 필요한 빈 상태/로딩/오류/취소를 텍스트로 그린다. 확인된 업무 데이터만 사용하고 가상 데이터는 샘플로 표시한다.

```text
{사용자}: 비교할 항목 선택 → 근거 확인 → 선택 결과 저장

목록 화면                        [주요 행동]
검색 [________________]  [검색]
이름          상태          변경일
{항목}        {상태}        {날짜}
  ↓ 행 선택
상세 화면/패널
{핵심 정보와 근거}
[저장]  [취소]
  ↓ 성공: 목록 상태 갱신 / 실패: 입력 보존·재시도 안내
```

한글 혼합 텍스트는 오른쪽 테두리를 닫지 않아도 된다. 와이어프레임의 박스는 화면 영역을 표현하며 구현에서 카드/테두리를 만들라는 뜻이 아니다.

기본은 가장 적합한 한 안을 제안한다. 구조적 선택이 중요한 경우에만 2~3개 대안을 짧게 비교하고 추천한다. 고정된 3안·카드형 대안·매 단계 승인·Freeze Gate를 강제하지 않는다. 사용자가 바로 구현을 요청했거나 범위가 확정됐으면 구현까지 이어간다.

구성은 과업으로 고른다: 정형 비교는 표/목록, 긴 읽기는 문서, 탐색은 목록/갤러리, 순서 의존 입력은 단계형. 자연스러운 여백과 좁은 화면에서의 핵심 행동을 확보한다. 이미 있는 컴포넌트를 재사용하고 팝오버/모달/편집기는 해당 제품의 접근성과 동작 계약을 따른다.

최종안의 주요 행동과 예외는 브라우저 인수 시나리오가 된다. 화면 제안이나 승인을 실제 기능 검증으로 설명하지 않는다.
