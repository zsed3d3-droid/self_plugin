# UX 저자 조사 A — 경험에서 실행 가능한 약속으로

확인일: **2026-10-29**. Sarah Doody, Irene Au, Luke Wroblewski, Dan Saffer, Andy Budd의 공식 홈페이지와 **공개 원문 14개**를 확인했다. 홈페이지·색인·접근 실패 링크는 원문 수에 넣지 않았다. 구조화된 출처·날짜·확인 상태·레시피는 [group-a.json](group-a.json)에 있다.

현재 상태는 모두 **후보**다. 저자의 주장, 우리의 구현 해석, 실제 실행 결과, 사용자의 선호를 구분한다. 사용자 현재 요구와 연결된 비공개 프로젝트 판단의 채택/거절 이유가 우선한다. 작은 실험과 검증을 거쳐 해당 화면·과업 범위에서만 승격하며 사용자 재평가 없는 선호는 미평가로 남긴다. 유료 책·강의 원문이나 에셋은 복사하지 않았다.

## Sarah Doody — 방법론 활동보다 다음 결정

공식 [홈페이지](https://www.sarahdoody.com/)와 [The UX Notebook 뉴스레터 페이지](https://www.sarahdoody.com/ux-notebook-newsletter/)를 확인했다. 현재 직함·고객 목록은 규칙의 근거로 재인용하지 않는다.

| 공개 원문 / 날짜 | 실제 확인한 주장·경험 |
| --- | --- |
| [Designing With Lenses](https://www.sarahdoody.com/designing-with-lenses/) · 2017-09-11 | 자신의 UX Notebook 재구상에서 조사에 기한을 둔다고 설명한다. 본문은 확인했으며 포함된 영상의 세 렌즈 이름은 확인하지 않았다. |
| [Are You Stuck In Research Mode?](https://www.sarahdoody.com/are-you-stuck-in-research-mode/) · 2016-01-23 | 방법론을 고르지 못해 시작하지 못하는 질문을 받은 경험에서 활동·도구의 과잉을 비판한다. |
| [Accelerate Failure](https://www.sarahdoody.com/accelerate-failure/) · 2017-11-28 | 가정을 오래 다듬기보다 일찍 배우는 문화를 제안한다. 측정된 효과를 제시한 실험 보고는 아니다. |

**철학의 핵심:** 문제 해결과 배움이 목적이다. 다음은 그 관점을 코딩 과업으로 옮긴 **우리의 제안**이다.

- **A-SD-1 — 조사 종료 조건:** “어떤 미확인 사실이 다음 결정을 바꾸는가”를 먼저 적는다. 명확한 국소 수정은 관련 근거만 읽고 구현한다. 문제·권한·영속 데이터의 위험이 불명확하면 조사 깊이를 유지한다. 같은 과업 재실행에서 놓친 조건이 있었는지 검증한다.
- **A-SD-2 — 관점으로 반박:** 첫 사용자/반복 사용자, 정상/복구처럼 유효한 대조 조건을 골라 같은 흐름을 확인한다. 이것은 원글 영상의 구체 렌즈를 재현한 것이 아니다. 사소한 수정에 근거 없는 persona나 워크숍을 늘리면 역효과다.

## Irene Au — 선택을 구체화하고 느껴지는 품질도 확인

공식 [홈페이지](https://www.ireneau.com/)와 아래 본문을 읽었다. 두 글의 현 사이트 `datePublished`는 **2025-12-15**지만 첫 글은 **2014–2017년의 집 설계 경험**을 회고한다. 게시·이전 메타데이터를 경험 발생일이나 최초 공개일로 단정하지 않는다.

| 공개 원문 | 실제 확인한 주장·경험 |
| --- | --- |
| [The Architecture of Creative Collaboration](https://www.ireneau.com/blog/the-architecture-of-creative-collaboration) | 의뢰인으로서 거친 대안과 점점 구체화되는 모형으로 선택의 손익을 이해한 경험. 저자가 A/B라 부르지만 무작위 대조 실험은 아니다. |
| [Rethinking the canonical design process diagram](https://www.ireneau.com/blog/rethinking-the-canonical-design-process-diagram-and-a-call-for-beauty) | 과거 직접 저비용 관찰 환경을 만든 일화와, 출시 뒤에도 만들고 검증하며 반복하자는 주장. 기능적 결과와 감각적 품질을 함께 보자고 제안한다. |

**철학의 핵심:** 선택 가능한 형태를 만들어 대화하고, 한 번의 출시로 끝내지 않는다. 다음은 **우리의 구현 해석**이다.

- **A-IA-1 — 갈등 있는 구조만 비교:** 목록/상세 병렬과 화면 전환이 다른 가치를 줄 때, 같은 콘텐츠로 낮은 비용의 대안을 비교한다. 이미 결정된 수정마다 대안 세 개를 만들 필요는 없다. 실제 포커스·touch·모션 문제는 저충실도 문서만으로 검증하지 않는다.
- **A-IA-2 — 기능/선호 분리:** assertion 통과와 사용자 원문·영역·과업·기기를 따로 기록한다. 좋아한 컴포넌트를 보존하고 지적한 축만 바꾸는 실험이 가능하다. 감각을 기능 결함과 섞거나 다른 화면의 전역 취향으로 승격하면 안 된다.

## Luke Wroblewski — 자신이 만든 개인 지식 도구를 계속 수정

공식 [홈페이지](https://www.lukew.com/)의 최신 링크를 확인하고, 기존 폼 레시피보다 범위를 넓혀 **자기 자료를 사용하는 Ask LukeW의 실제 변경 기록**을 골랐다.

| 공개 원문 / 날짜 | 실제 확인한 주장·경험 |
| --- | --- |
| [A New Retrieval System](https://www.lukew.com/ff/2157/ask-lukew-a-new-retrieval-system) · 2026-08-17 | 질문 유형을 나눠 검색을 수정했다. 자동 평가와 직접 비교가 어긋나 버그를 발견했다는 저자의 보고다. 원시 투표는 확인하지 않았다. |

**철학의 종합 해석:** 실제 질문과 소유 자료에 맞추고 사람이 결과를 직접 비교한다.

- **A-LW-1 — 검색 종류/판단 이력 보존:** 최신 판단, 과거 판단, 자료 찾기, 집계를 같은 답변 문제로 뭉개지 않는다. 동일 질문의 새/이전 검색을 비교한다. 저자의 가중치·chunk 설정을 최적값으로 복사하지 않는다.
- **A-LW-2 — 가능한 일을 먼저 알림:** 실제 가능한 예시와 자료 범위를 보여준다. 명시적 import와 원문 추적부터 시작한다. 화면 진입만으로 새 AI 작업을 돌리거나 개인 로그를 수집하는 것은 이 프로젝트의 허용 범위가 아니다. 삭제·중복 자료와 근거 연결을 재검증한다.

## Dan Saffer — 작은 동작과 기존 환경의 실제 제약

공식 [홈페이지](https://www.odannyboy.com/) 및 [저자 출판 목록](https://www.odannyboy.com/books/)에서 서명된 공개 원문으로 연결해 확인했다.

| 공개 원문 / 날짜 | 실제 확인한 주장·경험 |
| --- | --- |
| [New Book: Microinteractions](https://www.odannyboy.com/2012/07/new-book-microinteractions/) · 2012-07-09 | 상태 변경 같은 작은 상호작용의 상세를 다루는 출간 전 계획. 다섯 부분을 나열하므로 최종 책의 네 부분 모델을 확인한 근거로 쓰지 않는다. |
| [Tackling Maintenance Projects](https://boxesandarrows.com/tackling-maintenance-projects/) · 2002-11-04 | 밑줄을 링크라 추측했지만 숨은 설명을 여는 동작이었던 경험. 기존 실행·소스·제약을 먼저 알아야 한다고 설명한다. |
| [The UX of Commercial Drones](https://uxmag.com/articles/the-ux-of-commercial-drones) · 2014-01-09 | 배송 데모에 빠진 인수·상태 신호를 질문한 설계 제안. 운영 중인 드론의 실험 결과나 현재 규정은 아니다. |

**철학의 종합 해석:** 기술이 돌아가는 것과 사람이 상태를 알고 다음 행동을 하는 것 사이의 접점을 설계한다.

- **A-DS-1 — 작은 상태 계약:** 저장·전사·요약의 시작 조건, 진행, 완료, 실패, 취소/반복을 명시한다. 느린 응답·중복 클릭·재시도를 재현한다. 요청 ID와 stale 응답 처리는 우리의 코딩 제안이며 저자가 해당 앱에서 검증한 구현은 아니다. 모든 버튼에 spinner나 축하 효과를 붙이지 않는다.
- **A-DS-2 — 국소 수리와 구조 수리 구분:** 실제 동작과 연결된 상태를 먼저 확인하고 필요한 영역만 고친다. 국소 처방으로 과업이 해결되지 않을 때 구조를 바꾼다. 원글의 **외형을 기능보다 우선할 수 있다는 주장은 채택하지 않는다.**

**출처 제외:** 오래된 `microinteractions.com` 링크는 현재 책과 무관한 상업 사이트로 redirect되어 근거로 사용하지 않았다. 옛 O’Reilly 원문 링크는 일반 Radar 홈으로 이동해 원문 확인 수에 넣지 않았다. domain 소유·침해 원인까지 확인한 것은 아니다.

## 실제 적용과 승격

현재 증상에 맞는 **한 레시피**를 고르고 과업·화면·기기·근거를 기록한다. 원인 가설→작은 변경→동일 과업 재실행→장점/회귀 확인으로 이어간다. 자동 테스트·에이전트의 실행·사용자의 선호 상태는 분리한다.

이 문서의 레시피는 아직 우리 프로젝트에서 실험하거나 사용자가 승인한 결과가 아니다. 사용자 판단이 쌓이면 이유·반례·수정 결과까지 연결해 해당 범위에서 채택하고, 맞지 않는 조건을 계속 보존한다.
